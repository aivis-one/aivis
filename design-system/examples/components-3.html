K33 Auth shell

One main landmark, a heading, the form on a panel of the surface colour (white by day, the night surface), phone first: from the top on a phone, centred at desktop widths. The header holds the logo and the language and theme controls; the panel is at most the form width. K28 OTP input

Six cells in one labelled group. The first cell has autocomplete="one-time-code"; typing advances, Backspace steps back, the arrow keys, Home and End move, and a paste of the whole code fills every cell. The group is a left-to-right island and does not mirror. The component never submits: it fires ds-otp-change and ds-otp-complete.

K30 File input

A real input type=file in a labelled field. The limits are stated in text under it (JPG or PNG, up to 8 MB), and are checked on choosing: a file that fails is listed with its message (role=alert). Progress is a progressbar; the app sets it with AivisDS.file.progress / done / fail (the live field below fakes it with a timer). An image gets a local preview.

      K38 Combobox / user picker

      The ARIA 1.2 combobox: an input with role=combobox, aria-expanded, aria-controls and aria-activedescendant; a listbox of options with aria-selected; a polite result count. The look is the cabinet's user picker (search box, bordered result list with an avatar, name and a detail line, a chip for the chosen user). Down and Up move, Enter chooses, Escape closes. Text for the count comes from data-msg-count.

        K39 Reorder list

        An ordered list; every row has a move-up and a move-down button with a name that includes the row's title, as the cabinet's roadmap has them. The ends disable the button that cannot move. After a move the focus stays on the same button, the row is marked, and a polite status says where it went. No drag is built.
